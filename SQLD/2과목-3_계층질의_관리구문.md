## 1장. 계층형 질의 & 셀프 조인 ⭐⭐

### 1-1. 셀프 조인(Self Join)
- **같은 테이블을 2번 이상** 참조하는 조인 (FROM에 동일 테이블 2번)
- **테이블 별칭 필수** (식별 위해)
- 예: 직원-상사 관계 (`WHERE a.직원ID = b.상사ID`)

### 1-2. 계층형 질의(Hierarchical Query) — Oracle ⭐⭐
- 하나의 테이블 내 행끼리 계층(depth) 관계를 표현 (예: 조직, 사원, 메뉴)
```sql
SELECT 컬럼, LEVEL
FROM 테이블
START WITH 시작조건          -- 루트노드(최상위) 지정
CONNECT BY [NOCYCLE] PRIOR 연결조건;
```
- **START WITH**: 시작(루트) 위치. **루트노드는 LEVEL=1**
- **CONNECT BY PRIOR**: 행을 이어갈 조건
- **NOCYCLE**: 순환(A→B→A) 무한루프 방지

### 1-3. PRIOR 위치 (⭐ 방향 결정)
- `CONNECT BY PRIOR 자식 = 부모` → **부모 → 자식 (역방향 전개)**
- `CONNECT BY 자식 = PRIOR 부모` → 부모에서 자식으로
- 정리: **먼저 정해져야 하는 값의 방향에 PRIOR를 붙인다**
- ⚠️ WHERE 절은 START WITH·CONNECT BY 계층질의가 **모두 연산된 후** 수행 (그래서 조건에 안 맞는 상위 노드도 걸러짐)

### 1-4. 계층질의 가상 컬럼/함수
| 항목 | 기능 |
|------|------|
| **LEVEL** | 깊이(루트=1) |
| **CONNECT_BY_ISLEAF** | 리프노드(최하위)면 1, 아니면 0 |
| **CONNECT_BY_ROOT 컬럼** | 최상위(루트) 컬럼값 표시 |
| **SYS_CONNECT_BY_PATH(컬럼,구분자)** | 루트부터 현재까지 경로 표시 |
| **ORDER SIBLINGS BY** | 형제 노드(같은 LEVEL) 사이 정렬 |
| **CONNECT_BY_ISCYCLE** | 순환 발생 시 1 |

## 2장. PIVOT / UNPIVOT ⭐

### 2-1. 데이터 구조
| 구조 | 특징 |
|------|------|
| **Long Data(Tidy)** | 값이 여러 행으로 쌓임. RDB 설계 방식, **조인 가능**, 통계 분석용 |
| **Wide Data(Cross Table)** | 값이 여러 컬럼으로. 교차표, **조인 불가**, 보고서·요약용 |

### 2-2. 변환 방향 ⭐
- **PIVOT**: Long → Wide (**행 데이터를 열 데이터로**)
- **UNPIVOT**: Wide → Long (**열 데이터를 행 데이터로**)
```sql
-- PIVOT
SELECT * FROM (…) PIVOT ( COUNT(*) FOR DNAME IN ('ACCOUNTING' AS ACCOUNTING, …) );
-- UNPIVOT
SELECT * FROM PIVOT_TABLE UNPIVOT ( EMP_COUNT FOR DEPARTMENT IN (ACCOUNTING AS 'ACCOUNTING', …) );
```

## 3장. 정규 표현식(Regular Expression) ⭐

### 3-1. 기본 연산자
| 연산자 | 의미 | | 연산자 | 의미 |
|--------|------|-|--------|------|
| `.` | 모든 한 글자(newline 제외) | | `^` | 시작 글자(앵커) |
| `|` | or(대체) | | `$` | 마지막 글자(앵커) |
| `\` | 다음 문자를 일반 문자로 | | | |

### 3-2. 수량사
| 연산자 | 의미 |
|--------|------|
| `?` | 0회 또는 1회 |
| `*` | 0회 이상 |
| `+` | 1회 이상 |
| `{m}` / `{m,}` / `{,m}` / `{m,n}` | m회 / 최소m / 최대m / m~n회 |

### 3-3. 문자 클래스
- `[char…]` 리스트 중 한 글자 / `[^char…]` 리스트에 없는 한 글자
- POSIX: `[:digit:]`=[0-9], `[:alpha:]`=[a-zA-Z], `[:alnum:]`, `[:upper:]`, `[:lower:]`, `[:space:]`
- `\d`(숫자) `\D`(숫자 아님) `\w`(영숫자+_) `\W` `\s`(공백) `\S`

### 3-4. 정규식 함수 (Oracle)
| 함수 | 기능 |
|------|------|
| REGEXP_LIKE(s, pattern) | 패턴 일치 여부(조건, true/false) |
| REGEXP_REPLACE(s, pattern, replace) | 일치 패턴 치환 |
| REGEXP_SUBSTR(s, pattern) | 일치 패턴 반환 |
| REGEXP_INSTR(s, pattern) | 일치 시작 위치 반환 |
| REGEXP_COUNT(s, pattern) | 일치 횟수 반환 |
- match_param: `i`(대소무시) `c`(대소구분,기본) `n`(dot이 개행 매칭) `m`(다중행) `x`(공백무시)

## 4장. 관리 구문 — DML ⭐

### 4-1. DML 종류
INSERT / UPDATE / DELETE / SELECT / **MERGE** — 모두 **COMMIT/ROLLBACK 필요**

### 4-2. INSERT
- `INSERT INTO 테이블(열…) VALUES(값…)` 또는 전체 열: `INSERT INTO 테이블 VALUES(…)`
- Oracle: 한 번에 **한 행만** / SQL Server: 여러 행 동시 가능
- NOT NULL 제약 컬럼 누락 시 오류. 작성 안 한 컬럼은 NULL
- ⚠️ Oracle에서 `''` 삽입 → **NULL**로 입력됨 (IS NULL로 조회) / SQL Server는 빈 문자열

### 4-3. UPDATE
- `UPDATE 테이블 SET 열=값 WHERE 조건` — **다중 컬럼 수정 가능**
- ⚠️ WHERE 없으면 **모든 행 수정!**

### 4-4. DELETE
- `DELETE [FROM] 테이블 WHERE 조건` — 행 단위. WHERE 없으면 전체 삭제
- **DML이라 ROLLBACK 가능**

### 4-5. MERGE ⭐
- 참조 테이블 기준으로 **UPDATE/DELETE/INSERT를 한 번에** 수행
```sql
MERGE INTO 대상 T USING 소스 S ON (연결조건)
WHEN MATCHED THEN UPDATE SET …
WHEN NOT MATCHED THEN INSERT (…) VALUES (…);
```

> ⚠️ **DELETE vs TRUNCATE vs DROP** (초빈출)
> | | DELETE | TRUNCATE | DROP |
> |--|--------|----------|------|
> | 분류 | **DML** | **DDL** | **DDL** |
> | 롤백 | 가능(커밋 전) | **불가(오토커밋)** | **불가(오토커밋)** |
> | 대상 | 데이터 일부/전체 | 데이터 전체(구조 남김) | 데이터+구조 모두 삭제 |
> | 방식 | 한 행씩 | 전체 한 번에 | 객체 자체 제거 |

## 5장. TCL (트랜잭션 제어) ⭐⭐

### 5-1. 트랜잭션 & ACID
- 논리적 연산단위, 분할 불가 최소 단위, **All or Nothing**
- **원자성/일관성/격리성/지속성** (1과목 참고)

### 5-2. COMMIT / ROLLBACK / SAVEPOINT
- **COMMIT**: DML 결과를 DB에 영구 반영. 이후 ROLLBACK 불가
- **ROLLBACK**: 최종 COMMIT 시점 / SAVEPOINT 지점으로 원복 (COMMIT 이전으론 불가)
- **SAVEPOINT**: 트랜잭션 일부만 롤백 (`ROLLBACK TO 세이브포인트`). 동일 이름이면 나중 것이 유효

### 5-3. AUTO COMMIT 차이 ⭐
- **Oracle**: DML은 사용자가 COMMIT해야 종료 / **DDL은 AUTO COMMIT**
- **SQL Server**: 기본 AUTO COMMIT (DML도 성공 시 자동 커밋, 오류 시 자동 롤백)
- ⚠️ Oracle에서 DDL 실행 시 그 이전의 모든 DML도 **자동 커밋**됨!

## 6장. DDL (데이터 정의) ⭐⭐

### 6-1. 데이터 타입
| 타입 | 특징 |
|------|------|
| **CHAR(n)** | 고정 길이. 짧으면 공백 채움. 비교 시 `'AA' = 'AA '`(공백 무시) |
| **VARCHAR2(n)/VARCHAR(n)** | 가변 길이(최대 n). 비교 시 `'AA' ≠ 'AA '`(공백 구분) |
| **NUMBER(p,s)** | p=전체자리, s=소수자리. NUMBER(6,2)→1234.56 O, 12345.67 X |
| **DATE** | 날짜+시각 |

### 6-2. CREATE TABLE ⭐
- 테이블·인덱스 등 객체 생성. 소유자 명시 가능
- ⚠️ 테이블명/컬럼명 규칙: **반드시 문자로 시작**, A-Z/a-z/0-9/_/$/# 허용, 예약어 불가, 대소문자 구분X(기본 대문자)

### 6-3. CTAS (테이블 복제)
```sql
CREATE TABLE new AS SELECT * FROM old;        -- 데이터+구조 복제
CREATE TABLE new AS SELECT * FROM old WHERE 1=2;  -- 구조만 복제
```
- ⚠️ **CTAS는 제약조건 중 NOT NULL만 복제됨** (PK/FK/UNIQUE/CHECK 복제 X)

### 6-4. ALTER TABLE ⭐
| 작업 | 구문 |
|------|------|
| 컬럼 추가 | `ADD 컬럼 데이터타입` (여러개 시 괄호) |
| 컬럼 수정 | `MODIFY 컬럼` (SQL Server: `ALTER COLUMN`) |
| 컬럼명 변경 | `RENAME COLUMN old TO new` |
| 컬럼 삭제 | `DROP COLUMN 컬럼` (한 번에 하나만) |
| 제약 추가/삭제 | `ADD CONSTRAINT` / `DROP CONSTRAINT` |
- ⚠️ 컬럼 순서 변경 불가(재생성 필요). 추가 컬럼은 마지막에 위치
- ⚠️ **데이터가 있는 테이블에 NOT NULL 컬럼 추가 불가** → DEFAULT 주면 가능
- 컬럼 사이즈: 증가는 항상 가능, 축소는 데이터 있으면 제한

## 7장. 제약조건(Constraint) ⭐⭐⭐

| 제약 | 특징 |
|------|------|
| **PRIMARY KEY** | UNIQUE + NOT NULL, 자동 UNIQUE 인덱스 생성, 테이블당 1개, 복합키 가능 |
| **UNIQUE** | 고유(중복X), **NULL 허용**, UNIQUE 인덱스 자동 |
| **NOT NULL** | NULL 불가. (CTAS로 복제되는 유일한 제약) |
| **CHECK** | 값 범위 제한 (도메인) |
| **FOREIGN KEY** | NULL 가능, 여러 개 가능. 자식 테이블에 설정 |

### 7-1. FOREIGN KEY ⭐
- **자식 테이블**에 FK 설정. 참조(부모) 컬럼은 사전에 **PK 또는 UNIQUE**여야 함
- FK 생성 후 제약: 부모가 가진 값만 INSERT/UPDATE 가능, 자식이 있으면 부모 삭제 불가

### 7-2. 참조 동작(Referential Action) ⭐
**Delete/Modify Action (부모 삭제·수정 시)**
| 옵션 | 동작 |
|------|------|
| **Cascade** | 부모 삭제 시 자식도 삭제 |
| **Set Null** | 부모 삭제 시 자식 해당 필드 NULL |
| **Set Default** | 자식 필드를 Default로 |
| **Restrict** | 자식에 참조값 없을 때만 부모 삭제 허용 |
| **No Action** | 무결성 위반 액션은 취하지 않음 |

## 8장. VIEW & 기타 객체

### 8-1. VIEW ⭐
- 실제 데이터 저장 X, 테이블처럼 조회 가능한 **가상 테이블** (정의만 저장, 조회 시 쿼리 재실행)
- **장점**: 독립성(테이블 구조 변경에도 앱 영향 X), 편의성(복잡 쿼리 단순화), 보안성(민감 컬럼 숨김)
- **단점**: 뷰 정의 변경 불가, 삽입/삭제/갱신 제한, 인덱스 구성 불가
- 종류: 단순뷰(1테이블) / 복합뷰(2+테이블 조인)
- `CREATE [OR REPLACE] VIEW 뷰이름 AS 조회쿼리;` / `DROP VIEW 뷰이름;`
- ⚠️ 기본 테이블 삭제되면 뷰도 삭제됨

### 8-2. SEQUENCE
- 자동 연속 숫자 부여 객체. `INCREMENT BY`(증가값) `START WITH` `MAXVALUE` `MINVALUE` `CYCLE|NOCYCLE` `CACHE N`

### 8-3. SYNONYM(동의어)
- 테이블 별칭. `CREATE [OR REPLACE] [PUBLIC] SYNONYM 별칭 FOR 테이블;`
- PUBLIC(누구나 사용, PUBLIC으로 삭제) / PRIVATE(생성자만)

## 9장. DCL (데이터 제어) ⭐⭐

### 9-1. 개념
- 객체 권한 부여(**GRANT**) / 회수(**REVOKE**)
- 오라클 기본 유저: SCOTT(샘플, 패스워드 TIGER) / SYS(DBA ROLE) / SYSTEM(모든 권한 DBA)

### 9-2. 권한 종류
- **오브젝트 권한**: 테이블 대상 DML(SELECT/INSERT/…) — **테이블 소유자**가 부여/회수
- **시스템 권한**: 시스템 작업(CREATE TABLE 등 DDL) — **관리자**만 부여/회수

### 9-3. GRANT / REVOKE
```sql
GRANT 권한 ON 테이블 TO 유저;
REVOKE 권한 ON 테이블 FROM 유저;
```
- 동시에 여러 유저·여러 권한 부여 가능 / **여러 객체 동시 부여는 불가**
- ⚠️ 이미 회수된 권한 재회수 불가(오류)

### 9-4. ROLE(롤) ⭐
- 여러 권한의 묶음. DB에서 유저-권한 사이 **중개** 역할. SYSTEM 계정에서 생성
- ⚠️ **롤은 반드시 재접속해야 권한 부여됨** (일반 권한은 즉시 반영)
- ⚠️ 롤을 통해 부여한 권한은 **롤을 통해서만 회수** 가능(직접 회수 불가)

### 9-5. 권한부여 옵션 ⭐⭐
| 옵션 | 대상 | 특징 |
|------|------|------|
| **WITH GRANT OPTION** | 오브젝트 권한 | 중간관리자 부여 권한은 **중간관리자만 회수 가능**. 중간관리자 권한 회수 시 **제3자 권한도 함께 회수** |
| **WITH ADMIN OPTION** | 시스템/롤 권한 | 중간관리자 거치지 않고 **직접 회수 가능**. 중간관리자 회수해도 **제3자 권한은 남음** |

> 💡 암기: **GRANT OPTION = 연쇄 회수(제3자도 사라짐)** / **ADMIN OPTION = 제3자 권한 남음**

**Q2.** PIVOT은 어떤 방향 변환인가?
<details><summary>정답</summary>행 데이터 → 열 데이터 (Long → Wide)</details>

<details><summary>정답</summary>ON DELETE CASCADE</details>

<details><summary>정답</summary>자동 COMMIT된다 (롤백 불가)</details>

<details><summary>정답</summary>저장 X(가상 테이블, 조회 시 쿼리 재실행), 인덱스 구성 불가</details>
