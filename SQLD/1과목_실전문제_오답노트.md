## 📝 문항별 상세 해설

### Q1. 데이터 모델링의 특징 — 정답 ②※
모델링 3대 특징 = **추상화 · 단순화 · 명확화**.
- ② "**시스템 구현만을 위한** 사전 작업"류 보기는 **오답**(모델링은 구현 이전에 업무를 분석·설명하는 의미도 큼).
- ①(추상화) ③(단순화) ④(명확화)는 특징에 부합.
> ※ 보기 글자가 흐려 확정도는 낮음. "3특징(추상·단순·명확)에 해당하지 않는 보기"가 정답.

### Q2. 데이터 모델링의 설명 — 정답 ③※
- ③ "데이터베이스 구축(성능 향상)**만이 목적**"류 → **오답**. 모델링의 목적은 **정보시스템 구축**이며, 그 자체로 업무를 설명·분석하는 의미를 가짐(④가 옳은 서술).
> ※ 원문 대조 권장.

### Q3. 데이터 모델링 유의사항 — 정답 ③※  ⭐(내가 틀림)
데이터 모델의 **3대 유의점**(피해야 할 것): **중복(Duplication) · 비유연성(Inflexibility) · 부정합성(Inconsistency)**.
따라서 유의사항 = ① 중복 최소화 / ② 데이터 정의를 **프로세스와 분리**해 유연성 확보 / ④ 연관관계 명확히 해 일관성 유지.
- ③ "사용자 **프로세스·시스템 특성에 밀접하게 결합**"류 → **오답**. 데이터는 프로세스와 **분리**해야 유연성이 생김(②와 모순되는 보기가 정답).
> ※ ②와 ③ 문구가 비슷해 헷갈림. "데이터↔프로세스를 붙이라"는 쪽이 틀림.

### Q4. 데이터 모델의 유의점 — ※
중복/비유연성/부정합성 중 하나를 지문으로 설명하고 고르게 하는 유형.
- **중복**: 같은 정보를 여러 곳에 저장 → 정합성 위협
- **비유연성**: 사소한 업무 변화에도 데이터 구조가 잘 안 바뀜(데이터 정의와 프로세스가 얽힘)
- **부정합성**: 상호 연관된 데이터가 서로 다른 값으로 어긋남
> ※ 지문 원문에 맞춰 위 정의로 매칭.

### Q5. 데이터 독립성 — ※
[집중보강 2] 참고. 논리적 독립성(외부↔개념) / 물리적 독립성(개념↔내부).
> ※ 지문이 '무엇이 바뀌어도 무엇에 영향 없음'인지로 판별.

### Q6. 3단계 스키마 — 정답 ②(개념 스키마)※
- 지문이 "**모든 사용자의 관점을 통합**한 조직 전체 관점"이면 → **개념 스키마**.
- "사용자·View 개개인 관점" → 외부 스키마 / "물리적 저장 구조" → 내부 스키마.
> ※ 지문이 '물리적 저장'을 말하면 ③ 내부 스키마가 답이 됨 — 원문 확인.

### Q7. ERD 해석 — 정답 ④
고객⎯주문 관계에서 주문 쪽에 **필수참여 표시(|)**, 고객 쪽에 선택참여. 즉 "**하나의 주문은 반드시 한 명의 고객에 의해** 주문된다"가 규칙.
- ④ "하나의 주문은 고객이 있을 수도 없을 수도 있다" → **오답**(주문은 고객 없이 존재 불가).
- ①②③은 ERD의 차수·선택성과 일치.

### Q8. ERD 작성 원칙 — 정답 ④
ERD 배치 원칙: **가장 중요한(핵심) 엔터티를 왼쪽 상단**에 두고, 이후 발생 엔터티를 오른쪽·하단으로 배치.
- ④ "오른쪽 상단에 배치" → **오답**.
- ② 작성 순서(엔터티 도출→배치→관계설정→관계명)와 ③ 관계명 중요성은 맞음.

### Q9. 엔터티 식별 — 정답 ② 환자
"여러 명의 환자가 존재, 각 환자의 이름·주소 관리."
- **환자** = 여러 **인스턴스**를 갖고 이름·주소라는 **속성**을 가짐 → 엔터티.
- 병원 = 하나뿐(맥락), 이름·주소 = 속성. → 답 ② 환자.
> 💡 헷갈림 방지: "여러 개 존재 + 속성 보유" → 엔터티 / "그 엔터티를 설명하는 값" → 속성.

### Q10·Q11. 엔터티 특징 — 정답 ③, ①
- **Q10 ③**: 객체지향 싱글턴처럼 "한 개의 인스턴스만으로 충분"은 **오답**. 엔터티는 **2개 이상 인스턴스**의 집합이어야 함.
- **Q11 ①**: "다른 엔터티와 관계를 가지지 않는다"는 **오답**. 엔터티는 **최소 1개 이상 관계**를 가짐(단, 통계성·코드성 엔터티는 관계 생략 가능).

### Q12. 발생시점에 따른 엔터티 — 정답 ①
발생시점 분류 = **기본(Fundamental/Key) · 중심(Main) · 행위(Active)**.
- ① "관계 엔터티(Relation Entity)"는 이 분류에 **없는 용어** → 오답.

### Q13. 엔터티 명명 — 정답 ①
명명 규칙: 현업 업무용어 사용(②✓), 유일한 이름(③✓), 생성 의미대로(④✓), **약어는 가급적 지양**.
- ① "가능하면 약어를 사용" → **오답**.

### Q14·Q15. 속성 — 정답 ② 속성, ③
- **Q14 ②**: "의미상 더 이상 분리되지 않는 최소 데이터 단위" = **속성**(도메인 X).
- **Q15 ③**: "하나의 인스턴스에서 각 속성은 **하나 이상**의 속성값을 가질 수 있다" → **오답**. **1개 속성은 1개 값**(다중값이면 별도 엔터티/1차 정규화).

### Q17·Q18. 파생속성·도메인 — 정답 ①, ④
- **Q17 ①**: "조회 성능 위해 미리 계산·저장한 원래 속성값" = **파생 속성(Derived)**.
- **Q18 ④**: "속성이 가질 수 있는 값의 범위(타입·크기·제약)" = **도메인(Domain)**.

### Q19. 속성 명명 — 정답 ③
- ③ "직원·고객 엔터티에 **엔터티별로 동일한 속성명**(예:이름) 사용이 좋다" → **오답**. 속성명은 **전체 데이터 모델에서 유일**해야 함(그냥 '이름'보다 '직원명','고객명'처럼).

### Q20·Q21·Q23·Q24·Q25. 관계 — 정답 ④, ②, ②, ③, ④
- **Q20 ④**: 연관관계(존재)=소스코드 **멤버변수**, 의존관계(행위)=오퍼레이션 **파라미터**. 보기가 뒤바뀜 → 오답. [집중보강 4]
- **Q21 ②**: 관계 표기법 3요소 = **관계명·관계차수·관계선택사양**. "식별성"은 아님 → 오답. ※
- **Q23 ②**: 참여자 수(1:1, 1:M) = **관계차수(Cardinality)**.
- **Q24 ③**: 관계 연결을 가능하게 하는 건 **동사(Verb)**. "명사(Noun)" → 오답.
- **Q25 ④**: 관계 도출 확인 = (가)연관규칙 (나)정보조합 (다)규칙서술 (라)동사 → 모두.

### Q31. 식별자 종류 — 정답 ③
- (가)대표성O·유일구분 → **주식별자**
- (나)유일구분O·대표성X → **보조식별자**
- (다)업무적 의미 부여 → **본질식별자**
- (라)타 엔터티로부터 상속 → **외부식별자** → 답 ③. [집중보강 5]

### Q38. 반복속성 정규화 — 정답 ④
모델에 `A유형기능분류코드1 ~ I유형기능분류코드9` 처럼 **반복 컬럼**이 존재 = **1차 정규형 위반**.
- ① "반복 그룹이 칼럼단위 → 제1정규형" **오답**(오히려 1NF 위반).
- ④ "각각 인덱스 다 만들면 DML 성능 저하 → **1차 정규화 후 인덱스**가 옳다" **정답(적절)**.

### Q40. 정규형 정의 — 정답 ③
"릴레이션 R이 **⊙(2정규형)**이고, 기본키에 속하지 않은 속성 모두가 기본키에 **이행적 함수종속이 아닐 때 ⓒ(3정규형)**에 속한다."
- 3정규형은 반드시 **2정규형을 만족한 상태**에서 이행종속을 제거한 것 → ⊙=2정규형, ⓒ=3정규형. → 답 ③.
> ⚠️ ②(1정규형·3정규형)로 고르기 쉬운데, 3NF의 전제는 **2NF**임을 기억.

### Q43·Q44·Q45. 정규화 — 정답 ② 2차, ② 2차, ① 1차
- **Q43 ②**: "일반속성은 주식별자 **전체**에 종속" = **2차 정규형**(부분종속 제거).
- **Q44 ②**: 지도교수번호·학과명이 복합키 일부(학번)에 종속 → **부분종속 제거 = 2차 정규화 대상**.
- **Q45 ①**: 취미코드에 '노래,댄스' 같이 **여러 값(다중값)** → **1차 정규화**(원자값)로 분해.

### Q46·Q49. NULL — 정답 ①, ③
- **Q46 ①**: NULL = "**모든 값**을 의미한다" → **오답**. NULL은 **값이 없음/아직 모름**(0도 공백도 아님).
- **Q49 ③**: "`NULL = NULL`의 결과는 TRUE" → **오답**. NULL 비교는 **unknown**(참 아님). NULL 여부는 `IS NULL`로만 판별. [집중보강 6]

### Q48. 트랜잭션 — 정답 ②
순차작업 A·B가 "모두 수행 or 모두 취소" = **원자성(Atomicity)**.
- ② "A와 B를 각각 수행 후 **각각 커밋**" → **오답**. 하나의 트랜잭션으로 묶어 한 번에 COMMIT/ROLLBACK 해야 함.

### Q50. 본질 vs 인조 식별자 — 정답 ④
- ④ "인조식별자는 개발 편의성을 높여주므로 **되도록 사용하는 것이 바람직**" → **오답**. 인조식별자(대리키)는 **필요한 경우에만** 사용(남용 시 중복 데이터·불필요 인덱스로 품질↓). [집중보강 5]

### Q39·Q41·Q42·Q47 (원문 대조 필요) ※
- **Q39**: 3차 정규화 시 도출 엔터티 수 세기 문제. 반복속성(LAB이용…) 분리 + 이행종속 분리를 그림의 속성 목록대로 적용해 계산. 사진이 흐려 정확한 수는 원 그림으로 확인 필요.
- **Q41**: 정규화 설명 부적절 찾기 → [집중보강 7] 기준으로 판별.
- **Q42**: 조인 = **식별자 상속 + 상속된 속성을 매핑키(조인키, 보통 FK)로 활용**. 이 정의와 어긋나는 보기가 정답.
- **Q47**: 테이블 분리(부서 중복 제거) 관련 → 이행종속 제거(3차)인지 부분종속(2차)인지 그림의 함수종속으로 판별.

# 🔑 집중 보강 (자주 틀린 개념)

## [집중보강 1] 데이터 모델링 3특징 · 3단계

**3대 특징** — 추상화 · 단순화 · 명확화(정확화). (※ "구체화/일반화"는 오답 단골)
**3단계**: 개념적(추상화 최고, ERD) → 논리적(정규화, Key·속성·관계) → 물리적(DBMS·인덱스·성능).
- 정규화는 **논리적** 단계 활동!

## [집중보강 2] 데이터 독립성 & 3단계 스키마 ⭐ (Q22)

**3단계 스키마**
| 단계 | 스키마 | 관점 |
|------|--------|------|
| 외부 | 외부 스키마 | 사용자·View |
| 개념 | 개념 스키마 | 통합, 설계자 |
| 내부 | 내부 스키마 | 물리 저장, 개발자 |

**독립성 2종** (Q22 핵심)
- **논리적 독립성** = 외부 ↔ 개념 매핑. **개념(논리) 구조가 바뀌어도 응용/외부는 영향 X**.
- **물리적 독립성** = 개념 ↔ 내부 매핑. **저장장치·색인·파일 구조가 바뀌어도 개념/응용은 영향 X**.

> Q22 지문: "**파일 구조/색인 구조** 변화가 논리스키마·응용프로그램에 영향 X" → 저장구조 얘기 = **물리적 독립성**.
> 함정: '논리스키마'라는 단어에 낚여 ①논리적 독립성 고르기 쉬움. **변화의 주체가 물리(파일·색인)이면 물리적 독립성**.

## [집중보강 3] 엔터티 · 속성 분류 (Q9~15,17,18)

**엔터티 분류**
- 유·무형: 유형(교수·물품) / 개념(수업·상품) / 사건(주문·수강신청, 발생량 多)
- 발생시점: **기본(사원·부서)** / **중심(주문·계약)** / **행위(주문내역, 2개+부모)**

**속성 분류(특성)**: 기본 / 설계(코드·일련번호) / **파생(계산·통계, 최소화 권장)**
**규칙**: 1엔터티≥2인스턴스, 1엔터티≥2속성, **1속성=1값**(다중값→1차 정규화).

## [집중보강 4] 관계 — 존재 vs 행위 ⭐ (Q20)

| 구분 | UML | 표기 | 소스코드 |
|------|-----|------|----------|
| **존재에 의한 관계** | 연관관계(Association) | 실선 | **멤버변수**로 선언 |
| **행위에 의한 관계** | 의존관계(Dependency) | 점선 | 오퍼레이션 **파라미터**로 이용 |

> Q20 오답 포인트: 이 두 줄을 **서로 바꿔** 출제함. "연관=파라미터 / 의존=멤버변수"로 쓰면 틀림.
> ERD에서는 존재·행위를 **구분하지 않고** 표현.
> 관계 표기 3요소: **관계명 · 관계차수(Cardinality) · 관계선택사양(선택성)**.

## [집중보강 5] 식별자 & 식별자관계 vs 비식별자관계 ⭐⭐ (Q30,31,50)

**식별자 6종 분류**
| 기준 | 종류 | 설명 |
|------|------|------|
| 대표성 | 주식별자 / 보조식별자 | 대표O·참조연결O / 구분은O·대표X·참조연결X |
| 생성 | 내부식별자 / 외부식별자 | 스스로 생성 / 관계로 상속받음 |
| 속성수 | 단일 / 복합 | 1개 / 2개 이상 |
| 대체 | 본질식별자 / 인조식별자 | 업무로 생성 / 원조 복잡해 인위 생성(시퀀스) |

**인조식별자 주의(Q50)**: 개발은 편하지만 → **중복 데이터·불필요 인덱스** 유발 → **필요할 때만** 사용.

**식별자관계 vs 비식별자관계** (Q30 핵심)
| 항목 | 식별자 관계 | 비식별자 관계 |
|------|-------------|---------------|
| 연결강도 | 강함 | 약함 |
| 부모키 상속 | 자식 **PK로** | 자식 **일반속성(FK)로** |
| 표기 | **실선** | **점선** |
| 부모 존재 | 부모 있어야 자식 생성 | 부모 없이 자식 생성 가능 |

**비식별자 관계를 쓰는 4가지 정당한 사유** (Q30은 이 중 하나가 아닌 보기가 정답)
1. 부모 없이 **자식이 먼저 생성** 가능(약한 관계)
2. 부모 인스턴스가 자식보다 **먼저 소멸**
3. **SQL 조인 관계를 최소화**(PK 단순화)하고 싶을 때
4. 부모 주식별자를 상속받기보다 **자식에 별도 주식별자** 생성이 유리할 때
> 위 4가지에 해당하지 않거나, 오히려 "반드시 부모에 종속(강한 연결)"을 말하는 보기가 **부적절(정답)**. 원문과 대조해 확정하세요.

## [집중보강 6] NULL ⭐⭐⭐ (Q46,48,49)

- NULL = **아직 정의되지 않은 값**(모름/부재). **0(숫자)·''(공백)과 다름**.
- **NULL이 포함된 산술연산 결과 = NULL** (1000 + NULL = NULL).
- **NULL 비교(=, >, <)는 unknown** → `NULL = NULL`도 참이 아님. **`IS NULL`/`IS NOT NULL`로만** 판별.
- **집계함수는 NULL을 무시(제외)** — 0으로 치지 않음.
  - `COUNT(*)`=NULL 포함 전체 / `COUNT(컬럼)`=NULL 제외.
  - 전체 평균은 `AVG(컬럼)`(NULL 제외)와 `SUM/COUNT(*)`(NULL을 0 취급)가 **다를 수 있음**.
- NULL 치환: `NVL(값,대체)`, `COALESCE(...)`.
> Q46 함정: NULL을 "모든 값"으로 착각 / Q49 함정: `NULL=NULL`을 TRUE로 착각.

## [집중보강 7] 정규화 ⭐⭐⭐ (Q16,38,39,40,41,43,44,45,47)

**목적**: 중복 최소화·이상현상(삽입/삭제/갱신) 제거. **함수종속(FD) 기준으로 테이블 분해**.

| 단계 | 제거 대상 | 판별 키워드 |
|------|-----------|-------------|
| **1NF** | 반복속성/다중값 | 모든 속성이 **원자값**(Q38 반복컬럼, Q45 다중 취미코드) |
| **2NF** | **부분함수종속** | 일반속성이 **복합키 일부**에만 종속(Q16,43,44) |
| **3NF** | **이행함수종속** | 일반속성 A→B→C (Q40 정의) |
| **BCNF** | 후보키 아닌 결정자 | 모든 **결정자가 후보키** |

**핵심 구분법**
- 반복되는 컬럼/여러 값이 한 칸에 → **1차** 대상.
- **복합키**의 일부만으로 결정되는 일반속성이 있으면 → **2차** 대상. (예: (주문번호,상품코드) 키인데 상품명은 상품코드만으로 결정 → 상품 테이블 분리)
- PK가 아닌 속성이 또 다른 일반속성을 결정(A→B→C) → **3차** 대상. (예: 학번→지도교수번호→학과명)

> ⚠️ **정규화 ↔ 성능**: 정규화하면 중복↓·입력/수정/삭제 성능↑ 이지만 **조회는 조인이 늘어 느려질 수 있음** → 이때 **반정규화**(중복 허용, 조회↑). 단 반정규화가 조회향상을 **항상 보장하진 않음**.
> ⚠️ 3NF의 전제는 2NF (Q40).
